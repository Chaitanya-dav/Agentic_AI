🔒 5. The 9-Point Security Gate Matrix
Every action must pass all 9 deterministic security checks before the Execution Agent can settle:

Recomputed Current Payload Hash: Live re-canonicalization and SHA-256 hash match.
Checkpoint Hash Consistency: Suspension checkpoint matches live payload.
Token Payload Hash Match: Token cryptographically binds the identical hash.
Approval ID Anti-Replay Binding: Token binds the specific unique approval_id.
Time-to-Live (TTL) Expiry: Authorization timestamp is active.
Four-Eyes Enforcement: Approver identity is strictly distinct from Initiator.
Approval State Machine: Approval state is strictly APPROVED.
Single-Use Gate: Approval is not consumed (is_consumed == False).
Live Policy Boundaries: Real-time evaluation of risk level, limits, AML/sanctions registry, and account status.
⚠️ 6. Known Limitations & Production Roadmap
Database Engine: Uses SQLite in WAL mode with atomic CAS for local simplicity. In a high-throughput production deployment, PostgreSQL with row-level locking (SELECT ... FOR UPDATE) should be utilized.
Key Management: Uses HMAC-SHA256 with an application secret key. In multi-cluster production environments, an asymmetric key pair (Ed25519 or ECDSA) backed by AWS KMS or HashiCorp Vault is recommended.
LLM Provider Mode: Operates out-of-the-box with USE_MOCK_LLM=true for 100% offline determinism. If an OPENAI_API_KEY is provided in .env, it automatically switches to live LangChain/LangGraph OpenAI models.
